# 01-04: Establish module directory structure

**Goal:** Create directory structure for new modules following XMOS voice library patterns.

## Success Criteria

- Module directories created in `/workspace/modules/`: `lib_doa`, `lib_dtoa`, `lib_beamforming`, `lib_postproc`
- Each module has `api/`, `src/`, `tests/`, `doc/` subdirectories
- Module CMakeLists.txt follows `lib_aec` pattern
- API header stubs created for each module

## Implementation Steps

### 1. Create lib_doa module structure

```
modules/lib_doa/
    CMakeLists.txt
    api/
        doa_api.h          # Public API: doa_init(), doa_process_frame(), doa_get_estimate()
        doa_defines.h       # Constants, config parameters
        doa_state.h         # State structures
    src/
        doa_impl.c         # Implementation (placeholder)
        doa_priv.h         # Private internal definitions
    tests/
        CMakeLists.txt
        unit/
            test_doa_init.c
            test_doa_process.c
        data/
            test_scenarios.npy  # Synthetic test data
    doc/
        index.rst
        README.md
```

### 2. Create lib_doa API header stub

- Create `modules/lib_doa/api/doa_api.h`:

```c
#ifndef DOA_API_H
#define DOA_API_H

#include "doa_state.h"

// Initialize DOA module with 4-mic circular array configuration
void doa_init(doa_state_t *state);

// Process one audio frame and update DOA estimate
void doa_process_frame(doa_state_t *state, const int32_t (*mic_data)[FRAME_SIZE]);

// Get current DOA estimate (azimuth in degrees 0-360)
int32_t doa_get_azimuth(const doa_state_t *state);

#endif
```

### 3. Create lib_dtoa module structure

- Similar to lib_doa with API: `dtoa_init()`, `dtoa_process_frame()`, `dtoa_get_delays()`
- DTOA provides time difference between all mic pairs

### 4. Create lib_beamforming module structure

- Similar to lib_doa with API: `beamformer_init()`, `beamformer_set_direction()`, `beamformer_process_frame()`
- Placeholder for delay-sum and MVDR implementations (Phase 3)

### 5. Create lib_postproc module structure

- Similar to lib_doa with API: `postproc_init()`, `postproc_process_frame()`
- Placeholder for post-beamforming enhancement (Phase 4)

### 6. Create module CMakeLists.txt files

- Follow `lib_aec` pattern:

```cmake
add_library(fwk_voice_module_lib_doa STATIC)
target_sources(fwk_voice_module_lib_doa
    PRIVATE
        src/doa_impl.c
)
target_include_directories(fwk_voice_module_lib_doa
    PUBLIC
        api
)
target_link_libraries(fwk_voice_module_lib_doa
    PUBLIC
        lib_xcore_math
)
add_library(fwk_voice::doa ALIAS fwk_voice_module_lib_doa)
```

### 7. Update modules CMakeLists.txt

- Create `/workspace/modules/CMakeLists.txt` (for top-level module inclusion):

```cmake
add_subdirectory(lib_doa)
add_subdirectory(lib_dtoa)
add_subdirectory(lib_beamforming)
add_subdirectory(lib_postproc)
```

### 8. Create Unity test structure

- Create unit test files following `lib_aec` pattern
- Use `generate_unity_runner.py` script from fwk_voice
- Configure test build in `tests/unit/CMakeLists.txt`

## Notes

- Modules are standalone and portable (can be extracted to separate repos)
- API-only implementation for Phase 1; full implementation in later phases
- Test structure established but tests are stubs until modules implemented
- Module dependencies: lib_doa depends on lib_xcore_math, lib_dtoa is standalone
