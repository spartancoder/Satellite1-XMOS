# 01-01: Clone beamformer variant from fixed_delay baseline

**Goal:** Create `satellite1_firmware_beamformer` variant cloned from `satellite1_firmware_fixed_delay` with identical initial functionality.

## Success Criteria

- New variant builds successfully
- Build produces no errors and no new warnings compared to `fixed_delay` baseline
- Firmware flashes and runs with existing 2-mic configuration

## Implementation Steps

### 1. Create beamformer pipeline directory

- Copy `satellite-xmos-firmware/audio_pipelines/reference/fixed_delay/` to `satellite-xmos-firmware/audio_pipelines/reference/beamformer/`
- Rename library from `fixed_delay_aec_ic_ns_agc_2mic_2ref` to `beamformer_aec_ic_ns_agc_4mic_2ref` in CMakeLists.txt

### 2. Add beamformer pipeline to CMakeLists.txt

- Update `satellite-xmos-firmware/audio_pipelines/reference/CMakeLists.txt`:
  - Add beamformer library definition
  - Create alias `fph::ffva::ap::beamformer`
- Update `satellite-xmos-firmware/audio_pipelines/CMakeLists.txt`:
  - No changes needed (reference subdirectory includes all variants)

### 3. Create beamformer firmware variant targets

- Update `satellite-xmos-firmware/CMakeLists.txt`:
  - Add `beamformer` to `FFVA_PIPELINES_INT` list
- Update `satellite-xmos-firmware/satellite1.cmake`:
  - The foreach loop automatically creates targets for new pipeline name

### 4. Verify build

- Build `satellite1_firmware_beamformer` using standard build commands
- Compare warnings to `satellite1_firmware_fixed_delay` baseline
- Fix any new warnings before proceeding

## Verification

```bash
# Build both variants
make satellite1_firmware_fixed_delay
make satellite1_firmware_beamformer

# Verify build succeeds and compare warnings
```

## Notes

- The variant name `beamformer` is distinct from `fixed_delay` to enable parallel development
- Initial functionality is identical to `fixed_delay`; changes for 4-mic and DOA come in subsequent plans
- Firmware variant naming follows existing pattern: `satellite1_firmware_<variant_name>`
